# Privacy and network access

Publishing Ravenshelf's source does not grant repository visitors access to your laptop. Ravenshelf does not provide a remote-control server, and it does not upload your installed-game inventory to a Ravenshelf service. Using online features still sends requests to the sites involved, which can see the IP address used for those connections.

## What is public on GitHub

The publication review on 6 November 2026 checked the published 0.2.3 source, both commits, release metadata and public build logs. It found no personal laptop paths, personal email addresses, saved download history, browser profiles, real session cookies or known private download identifiers in those materials. The repository owner name and GitHub no-reply commit identity are public by design.

The public Windows release is built on GitHub-hosted Windows machines from the tagged source. Paths in those build logs belong to the hosted runner. Network addresses and credentials in tests are fixtures, not a record of the developer's network or accounts. This is a scoped review, not proof that every future change or dependency is free of privacy defects.

## Picture loading (0.10.4)

From 0.10.4, pictures already loaded are kept in memory for up to 30 minutes (at most 40 MB of downloaded picture data). They are never written to disk and are gone when Ravenshelf closes. To cancel pictures of pages you left, the window gives each picture request a number, and reports the numbers of pictures that left the page to Ravenshelf's own main process; the numbers are counters, not addresses, and never leave your PC. **Settings → Picture loading** counts this session's picture requests by site and result. It holds only site names (at most 30, then "Other sites") and counts: no picture addresses, game names or browsing history. It is not saved, not sent anywhere, and resets when Ravenshelf closes. Picture requests keep the checks described in [Image-request hardening](#image-request-hardening-in-024); image hosts still see the IP address used to connect.

## Background mode (0.10.3)

From 0.10.3, the background choice hides the window while leaving the app running. Previously enabled downloads, catalogue refresh, update checks, browser connector and protection-list refreshes continue; optional clipboard recognition and torrent work also continue when enabled. Torrent uploads remain subject to the existing sharing settings. Hiding the window does not hide your IP address or stop these network requests. It does not turn on disabled features, add Windows autostart or keep a sleeping computer awake. Use **Exit Ravenshelf** to stop the running app; hiding it does not install a staged update.

The added browser Save handling uses existing download events and the media URL supplied by the browser's right-click menu. It adds no extension permissions, broad page scraping, browser-cookie access, dependencies or telemetry. Private-window downloads, local addresses and URL credentials are excluded. Only the page origin is passed as context; active signed download URLs remain necessary to request a file. Browser-created media and protected or login-dependent streams are not universally capturable. Automatic captures keep a hidden window hidden, but accepting a capture still creates an in-memory review and can cause the existing link-check requests described below. Review cards are discarded on a full exit; files already added to the download queue follow the existing local persistence rules. Hiding the window keeps reviews in memory until their normal expiry.

## What leaves your computer during normal use

From 0.10.1, browser page context is reduced to its origin before it crosses the local connector. The actual selected download URL is preserved because signed links may need their query parameters. Provider referrer and form-context headers retain a clean page path only where the provider needs it; queries and fragments are removed, and a redirect to another origin reduces those headers to the origin. Completed ordinary browser downloads no longer retain their URL query tokens or request headers. Active and paused signed links remain in the local queue for resume.

Saved-library recovery files are local and can contain the original private URLs, paths or legacy credentials. They are never uploaded automatically. Keep these files private along with the rest of the profile; recovery does not scrub older backups. From 0.10.2 Ravenshelf keeps at most 5 recovery copies beside the library (the oldest, the newest, and any copy just reused) and deletes the others.

Those Internet services can see the connection's public IP and normal HTTP information. Depending on the request, they may also receive a user-agent, referrer, cookies or a game search term. Ravenshelf's own application code has no analytics endpoint or automatic upload of the installed-games scan. That does not make external websites anonymous or prevent their own logging.

Ravenshelf does not configure, verify or enforce a VPN or proxy. Browser traffic and Node-based file requests can follow different proxy settings. A proxy enabled only in your browser should not be assumed to cover Ravenshelf's downloads. Popup blocking and download checks do not hide your IP address.

Proxy/VPN binding and a kill switch are deferred. Binding a connection to an interface alone would not establish leak prevention across DNS, IPv4/IPv6, redirects and the separate browser/network stacks. Brave Search API integration is also deferred; using a search API would not make requests anonymous or establish a permanently free service.

## Data kept locally

Ravenshelf's Windows profile stores settings, saved collections, download queue/history, installed-game metadata and separate host-browser session data. Download records can include local paths and signed URLs. Request headers (host cookies, referrers) are saved only when Windows-account encryption succeeds in 0.3.1 (see below). Other browser state also remains in that profile. Downloaded files and partial-transfer support files live in the selected download folder.

Treat these files and backups as private. They are not a secure vault: another local account or program with sufficient file access may be able to read them. Do not publish the profile, `library.json`, `installed-games.json`, cookies, signed links, `.atlas-part` files or `.atlas-segments-*` folders. The repository's ignore rules help avoid accidental commits, but cannot prevent someone deliberately uploading a file.

The updater stages its candidate, job information and result beneath `updates/pending/` in the profile and copies critical profile files to `updates/backups/` before applying an update. These copies can contain the same sensitive paths and URLs as the original profile. They are not cloud backups and are not a complete copy of every browser partition or downloaded file. Sigstore's public key metadata is cached in `updates/sigstore/`; it contains no personal data.

From 0.4.2, Ravenshelf removes what a finished update leaves behind: the staged copy and helper in `updates/pending/`, and the previous executable that the update helper keeps next to the app as `.ravenshelf-rollback-….exe`. A rollback copy is removed only when the update's own record shows it succeeded and the copy matches, byte for byte, the executable that update replaced. After a failed update, the rollback copy and its record stay. Profile backups in `updates/backups/` are kept.

### Browser extension

The extension keeps its switches, the app's language and digits, the protection-list version and the browser's blocking rules in the browser's extension storage. For tabs showing a FuckingFast or FileKeeper page, it keeps that page's address so it can return you there after a blocked redirect; it uses the browser's session storage for this, which the browser holds in memory and clears when it closes. It keeps no browsing history and adds nothing to your downloads list for files Ravenshelf takes over.

In Ravenshelf's profile, `browser-host` holds the connector, its browser manifests and, while Ravenshelf runs, `endpoint.json` with the pipe name and the random token for that session (removed when Ravenshelf fully exits; retained while the window is hidden). `browser-extension` holds the folders your browsers load, `threat-lists` the downloaded lists, and `virustotal.json` your key sealed with Windows protected storage, plus your VirusTotal options. Connecting adds `NativeMessagingHosts` entries for Chrome, Edge, Brave and Firefox under your user's registry (`HKCU`); turning the switch off removes them. Reviews of browser downloads are kept in memory only and expire; one you download becomes a normal queue entry.

On www.youtube.com the extension adds its player button. The script reads the page's address when you choose a quality, never the page's content, and sends it only to the extension, which passes the video's ID to Ravenshelf. Its on/off switch is kept in the extension's storage.

aria2 is stored in `%LOCALAPPDATA%\Ravenshelf\torrent-tools`. Ravenshelf's profile folder `torrents` holds the checked file list of each torrent in your queue (`files\<info-hash>.torrent`, kept so a paused torrent can resume without asking other people again; lists of torrents no longer in the queue are deleted when Ravenshelf starts). aria2's DHT file (its list of other computers and its own random identity) is deleted before aria2 starts and after it stops, also when it ends on its own. While a torrent's file list is looked up, aria2 saves it briefly in a temporary folder there, deleted right after. A torrent's queue entry keeps its magnet link and the names of its files. Magnet links that wait for setup, and torrent reviews, are kept in memory only, for up to an hour. While a torrent downloads, its files are in a working folder named `.atlas-torrent-…` in the download folder; aria2 keeps its progress file there, and the folder is removed when the torrent is complete. A torrent cancelled or failed before it finished keeps that folder until you choose **Delete files** for it. aria2 keeps no log.

On fitgirl-repacks.site the extension's magnet script only notices a left click you make on a magnet link, and sends that link to the extension, which passes it to Ravenshelf. It reads nothing else on the page. In private windows, or with **Open FitGirl magnet links in Ravenshelf** turned off, the extension does not pass the link to Ravenshelf, and the browser opens it as before.

The YouTube helper programs are stored in `%LOCALAPPDATA%\Ravenshelf\media-tools`, with yt-dlp's and Deno's caches (YouTube player data, no personal data). Each YouTube download uses its own temporary folder there, removed when the download ends, and a private working folder next to the file, removed when it finishes. Videos waiting for setup are kept in memory only, for up to an hour.

On www.nexusmods.com the extension's page script only reads: the page's address, the game and mod names in the page's title lines, the address the page gives for itself, the game's and the mod's numbers and, on a file's page, the file's name and number. It adds nothing to the page, presses nothing and makes no requests, and it does not read your account, your sign-in or anything else on the page. It does notice that you clicked or pressed Enter or Space on the page (not where or what), so that it can send its note again, and whether the tab is visible. The extension keeps what it read for each open tab in the browser's session storage (in memory, for at most 50 tabs, cleared when the browser closes). It forgets a tab's note when the tab closes, leaves Nexus Mods or moves to a page that is not about a mod, stops using a note after half an hour, and forgets all notes when you turn off **Sort Nexus Mods files by game**. Nexus Mods pages in private windows are never read.

A mod file you download is saved under `Mods\<game>` in your download folder, and its queue entry records the game's and mod's names and numbers. A Nexus Mods download link carries a short-lived signature and can include your Nexus Mods account number. For a file recognised as a mod file, the queue entry keeps that link, and only the origin of the page it came from (sealed like other saved headers), while the download is waiting or unfinished, because they are needed to continue. Once the file has finished or you cancel it, only the plain address of the file is kept. An unrecognised Nexus Mods file follows ordinary browser-download rules: active, paused and cancelled entries retain their signed link for retry, while completed entries discard the query tokens and request headers. A one-way SHA-256 source identifier remains locally for duplicate detection; it is not sent to a server.

Firefox asks extensions to declare the data they transmit. Ravenshelf's extension declares browsing activity, because download and page addresses go to the Ravenshelf app on your PC, and website content, because the game, mod and file names that a Nexus Mods page showed go there with a mod file you download. Nothing goes to the developer or any other service.

Local game suggestions use existing saved/completed-game genre information. Adaptive accents sample an already loaded cover locally. Neither feature sends a preference model or image pixels to an additional service. Normal catalogue and cover requests still occur.

### PC specs

The **PC specs** page shows the processor, graphics adapters, memory, drives, display and Windows version. Ravenshelf reads them only when you open the page, choose **Check again**, or first choose **Compare with this PC** in a game's details, by running a fixed, read-only script with Windows PowerShell. The script asks Windows only for the model names, sizes and capability levels it prints. It never asks for serial numbers, the computer's name, user names, volume labels or network addresses. A graphics adapter's device path is looked at only to pick out its maker and model numbers and how it is connected; the rest of the path is not kept.

The answer stays in Ravenshelf's memory until you close the app. It is not written to the profile or any file, not included in logs, not sent to any site or service, and not shared with the browser extension. A drive's model name is whatever Windows calls the drive, which is normally its maker's model and can be a name someone gave it.

One exception is outside Ravenshelf: if an administrator has turned on PowerShell transcription or logging for the PC (Windows policies used in some workplaces), Windows itself can record the script and what it prints, including this answer.

**Can you run it?** (0.9.0) uses the same answer, read the same way, when you choose **Compare with this PC** in a game's details (or at once, after the specs have been read). The comparison is worked out in Ravenshelf on this PC and shown in the window; it is not saved or sent anywhere.

### Optional clipboard recognition

Clipboard recognition is off by default. While enabled, Ravenshelf reads text periodically, recognizes only supported HTTPS host/paste links, and keeps at most 100 recent link entries in memory for up to 30 minutes. It does not save a clipboard history or log the clipboard text. Turning it off or closing the app clears its entries. Other clipboard text is inspected transiently to recognize supported links; do not treat the feature as reading only preselected text.

Recognition and **Inspect link** make no network requests on their own. Inspect fills the import form; **Check links** is a separate user action that sends the selected URLs to their destinations. Encrypted-paste fragments and temporary file links can still be sensitive even while held locally.

### Verification and notifications

Manual checksum verification reads only the selected manifest and files beneath the selected folder, subject to path and size checks. It does not upload them or their results. Desktop notices are local Windows notifications with generic completion/problem/update messages; they omit game names, filenames and paths. Disable **Desktop notifications** or adjust Windows notification settings if preferred.

See [the user guide](USER-GUIDE.md#local-data-and-troubleshooting) for the profile location and [SECURITY.md](../SECURITY.md) for safe reporting. Redact usernames, personal paths and private links from screenshots or logs before sharing them.

## Microsoft Defender scans

Ravenshelf asks the Microsoft Defender already installed in Windows to scan each finished download. The scan runs on your PC through Windows; Ravenshelf sends nothing to Microsoft itself. Depending on your Windows Security settings (cloud-delivered protection and automatic sample submission), Defender may send file information or samples to Microsoft, as it does for any file on your PC. You can turn automatic scans off in **Settings → Scan finished downloads**.

## Saved-header encryption and 0.3.1 fallback behavior

Request-header encryption was introduced in 0.2.5. It uses Electron `safeStorage`, which on Windows uses DPAPI keys tied to your signed-in Windows account. Headers that cannot be decrypted are discarded; Ravenshelf refreshes the affected source link before making a resumed file request. Nexus Mods files are the exception: they are never looked up again and continue at their own link, without the page address.

Version 0.3.1 removes the older plaintext fallback. If encryption is unavailable or fails, headers remain in memory for the current session, while the saved queue contains empty headers and a marker requiring refresh. The app shows a warning. Queue records and partial files are kept, but after restart an affected download must resolve its source link again; it can need another browser step or fail if fresh access cannot be obtained. Ravenshelf does not send the resumed file request with silently missing credentials.

Opening an older queue removes its plaintext headers from the current saved `library.json`, sealing them when possible or omitting them when encryption fails. This does not erase older backups or other copies. Signed URLs and local paths are not covered by header encryption, so the rest of the profile remains sensitive.

The protected host browser's own Chromium cookie database is also encrypted on disk from 0.2.5 onward. This change is one-way: if you later run 0.2.4 or older with the same profile, the host windows will not be able to read those sessions and may ask you to complete host checks again.

Encryption at rest reduces exposure from copied header data and other Windows accounts. It does not protect against malware or another program already running as your Windows user, which can ask Windows to decrypt the same data.

## Image-request hardening in 0.2.4

Version 0.2.4 routes catalogue images through Ravenshelf's checked HTTPS transport, rejects private/local IP destinations at connection time and after redirects, and does not attach browser-session cookies or referrers to image requests. Responses are limited to 12 MiB and 15 seconds and must have a matching PNG, JPEG, GIF or WebP type and file signature; SVG and HTML are rejected. The renderer's content policy blocks direct remote images. Automated checks cover these boundaries, including private DNS answers, redirects and stalled or oversized responses.

These checks concern where images can connect; they do not conceal the connecting IP or certify an image host as trustworthy. The older 0.2.3 executable does not have this guard; download 0.2.4 or newer for this protection.

## Limits

Ravenshelf's transfer validation and protected host windows are not an antivirus scan. A valid link or successfully downloaded archive can still contain harmful software. Ravenshelf does not automatically extract archives or run downloaded installers. The installed-game scan reads local metadata without launching the programs it finds.

No source review can guarantee that a laptop is inaccessible or free of malware. Windows account permissions, other installed software, browser extensions and services outside Ravenshelf are separate from this project's protections.
